# BLOCKDASH — 3D 웹게임 1차 프로토타입

크런커처럼 각진 로우폴리 느낌의 3D 아레나에서 빠르게 이동하며 빛나는 홀로그램 표적에 빛을 맞혀 점수를 얻는 **싱글플레이 웹게임**입니다. 크런커의 코드·그래픽·상표를 복제하지 않고 새로 구성했습니다.

## 1. 이번 버전에서 플레이 가능한 것

- 3D 1인칭 화면 + 마우스 시점 회전, 모바일 터치 드래그 시점 회전
- WASD 이동, Shift 달리기, Space 점프, C/Ctrl 슬라이드
- 아이패드/폰: 왼쪽 가상 스틱, 오른쪽 시점 드래그, TAG/점프/슬라이드 버튼
- 장애물과 벽 충돌, 3D 아레나, 표적 5개가 위치를 바꾸며 반복 등장
- 90초 라운드, 표적 태그당 10점, 브라우저에 최고 점수 저장
- 일시정지 및 재개, 라운드 재시작, PC/터치 대응 HUD

**주의:** 아직 AI 대전과 실시간 멀티플레이, 서버와 계정은 구현하지 않았습니다. 이 버전은 조작과 렌더링 검증용입니다. 현재 슬라이드는 정해진 시간 동안만 지속되는 단순형이며, 크런커의 고급 슬라이드 호핑 시스템과 동일하지 않습니다.

## 2. 프로젝트 구성

```text
blockdash-fps/
├── index.html                 # HUD, 시작 화면, 조작 버튼, Three.js import map
├── src/
│   ├── game.js                # 아레나, 캐릭터, 충돌, 시점, 터치 조작, 게임 상태
│   └── style.css              # PC·태블릿에 반응하는 인터페이스
├── .github/
│   └── workflows/
│       └── deploy.yml         # GitHub Pages 자동 배포
└── README.md
```

**외부 의존성:** Three.js v0.180.0을 jsDelivr CDN으로 로딩합니다. 따라서 사용자의 브라우저가 해당 CDN에 접근할 수 있는 인터넷 연결이 필요합니다. npm 설치나 빌드 과정은 필요하지 않습니다.

## 3. PC에서 실행

압축을 푼 폴더에서 터미널 열기:

```bash
cd blockdash-fps
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 엽니다. Windows에서 `python3`가 없으면 `py -m http.server 8000`을 시도합니다. 파일을 더블클릭하여 `file://`로 여는 대신 로컬 서버를 쓰는 것이 안정적입니다.

브라우저에서 **게임 시작**을 누르면 마우스 포인터가 게임 안에 잠깁니다. 화면이 정지된 것 같다면 시작 버튼이 보이는지 확인하고 다시 클릭하세요. `Esc`를 누르면 일시정지합니다. 마우스 잠금이 지원되지 않는 환경에서는 마우스 버튼을 누른 채 드래그하는 것으로 시점을 움직일 수 있습니다.

## 4. 아이패드에서 실행

가장 쉬운 방법은 아래의 GitHub Pages 배포 주소에 Safari로 접속하는 것입니다. 가로 방향을 추천합니다.

- 왼쪽 동그라미: 이동. 끝까지 밀면 빠르게 달리기
- 오른쪽 화면: 손가락 드래그로 시점 회전
- `TAG`: 홀로그램 표적을 태그, 누르고 있으면 반복
- `점프`: 점프
- `슬라이드`: 이동하면서 누르면 짧은 슬라이드

테스트 중 iPad가 터치 대신 마우스/트랙패드를 기본 포인터로 인식한다면 모바일 조작 UI 표시 여부를 점검해야 합니다. Safari의 동작은 iPadOS 버전과 입력 장치에 따라 다를 수 있습니다.

## 5. GitHub Pages 배포 — 권장

1. GitHub에 로그인하고 `blockdash-fps`라는 **Public** 저장소를 새로 만듭니다. README 자동 생성 옵션은 체크하지 않는 편이 단순합니다.
2. ZIP을 압축 해제하고 **폴더 자체가 아니라 폴더 안의 내용** (`index.html`, `src/`, `.github/`, `README.md`) 을 저장소 최상위에 업로드합니다. 파일 업로드 시 숨김 `.github` 폴더를 빠뜨리지 마세요. 로컬 Git 사용이 가능하면 전체 파일을 한 번에 push 하는 것이 가장 확실합니다.
3. 저장소의 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
4. **Actions → Deploy BLOCKDASH to GitHub Pages** 워크플로가 성공했는지 확인합니다. 필요하면 **Run workflow**를 누릅니다.
5. 주소: `https://<GitHub 사용자명>.github.io/blockdash-fps/`

GitHub Pages는 정적 웹사이트만 제공하므로 1차 싱글플레이는 여기서 작동하지만, 추후 친구 대전용 실시간 서버는 별도로 호스팅해야 합니다.

### `.github` 업로드가 어려울 때

워크플로 없이도 `Settings → Pages → Build and deployment → Source → Deploy from a branch → main / (root)`로 배포할 수 있습니다. 이 프로젝트는 빌드가 없는 정적 웹페이지여서 두 방식 중 하나면 됩니다.

## 6. 다음 단계 (멀티플레이)

- `src/game.js`에서 플레이어 이동, 입력, 렌더링과 상태를 독립 모듈로 분리
- Colyseus 등 WebSocket 실시간 서버 도입: 방 생성 및 친구 초대, 플레이어 위치 전송
- **서버가 게임 상태의 기준**이 되도록 하여 순간 이동, 점수 조작 등의 비정상 입력을 검증
- 다른 플레이어의 이동을 보간해 자연스럽게 표시, 재접속 복구
- 싱글플레이 AI 봇, 맵 선택, 전적 및 랭킹 연동 (Supabase 등)
- PC·iPad 최적화와 실제 기기별 입력/프레임 테스트

## 7. 문제 해결

- **게임이 하얗거나 검게 나오고 시작 버튼을 눌러도 변화가 없음**: 인터넷 연결, jsDelivr CDN 차단 여부, 브라우저 개발자 콘솔 확인. Three.js 모듈을 못 읽으면 게임 코드가 실행되지 않습니다.
- **사이트에서 404 오류**: 저장소 최상위에 `index.html`이 있는지, Pages 소스가 알맞게 설정되었는지, Actions 배포가 성공했는지 확인.
- **아이패드에서 버튼이 안 보임**: 가로 모드로 회전하고 Safari에서 접속. 고정형 가상 컨트롤은 `pointer: coarse`가 감지된 환경에서 나타납니다.
- **터치 조작이 겹침**: 작은 화면에서는 가로 모드 권장. 실제 기기에서 조작 버튼 위치와 안전 영역 확인 필요.
